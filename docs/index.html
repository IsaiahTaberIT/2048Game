How To Play

Controls:

Use WASD to slide tiles Up, Left, Down, Right Respectively.
Or use the arrow keys to the same effect.
Press "R" to reset. Especially if you get stuck
Pressing "P" secretly toggles hardmode, there is no UI indication that it is on or off aside from the fact that the game rapidly becomes impossible.

Goal:

Combine tiles with matching numbers to create new tiles.
Obtain the 2048 tile to win.
Or try and survive as long as possible to get a highscore!

How it works

Under the hood the grid is a 2D array, when a movement key is pressed a two pointer approach is used to decide how the tiles move and if they will merge. One pointer keeps track of the next possible movement position, and the other pointer points to the next potential tile to move. The direction the pointers move is dependent on which key is pressed, and the checking process is repeated for each row/column depending on movement direction.

if any tile has successfully changed position after a movement key is pressed, 1-2 new tiles with either a value of 2 or 4 are spawned.

Flaws/Self Critique

After a human gestation period since finishing this project, it would be horrifying if I hadn't improved at all as a developer, so here are all the notable problems with the project:

  1. The code for each of the movement directions is nearly identical and is repeated 4 times. This behavior should've been extracted to a method
  2. Redundant re-creation array of tiles whenever a movement happens
  3. Variable Names aren't very good
  4. Calling tempobj.GetComponent<NumberValues>().value everytime "value" needs to be accessed.
  5. In this line: NumberValues = tempobj.GetComponent<NumberValues>(); the variable has the same name as the class.
  6. in addition "NumberValues" the variable is never used, which makes issue 4 just absolutely maddening.
  7. just overcomplicated, if I were making this today I would just use a flat array instead of a 2D array.
  8. the world grid is defined like this: GameObject[,] Coords = new GameObject[40, 40];
    why is it 40x40?
  9. the color for all of the squares is recalculated every frame, and not just when they are changed / instantiated.
  10. Using the "Color32" class instead the of "Color" class forced me to do so much casting between integers and bytes.
  11. Bad UI.
  12. No saving scores across sessions.
  13. No win state.
  14. No Lose state, just softlocks until reset.
